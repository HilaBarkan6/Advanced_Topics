1. Logging 
        We have implemented a logging system to improve the observability and debuggability of our project.

        Description:
        - The logging system provides centralized, structured logging throughout the application.
        - Each log message includes a timestamp and a severity level (INFO, WARNING, ERROR).
        - Log messages are written to a log file located in the log_output directory.
        - The system includes helper methods (logInfo, logWarning, logError) for convenience.

        Design Highlights:
        - Logger::log(level, message) handles both console and file output.
        - Logger is non-copyable and cleans up resources in its destructor.
        
        This design improves observability and helps with debugging during development and testing. 

        The code is located in:
        src/Logger/Logger.h
        src/Logger/Logger.cpp

2. Configuration File
        We implemented a configuration system using a singleton `Config` class.

        Description:
        - The configuration system allows loading key-value pairs from a configuration file at runtime.
        - The configuration file is expected to contain lines in the format: key=value.
        - Internally, the configuration is stored in an `unordered_map<std::string, std::string>` for fast retrieval.
        - The class provides methods to retrieve values as strings, integers, or booleans, with support for default values.
        - The implementation uses the Singleton design pattern to ensure that only one instance of the `Config` object is created and used throughout the application.

        Design Highlights:
        - `Config::getInstance()` returns a reference to the unique configuration object.
        - `Config::loadFromFile(filename)` loads settings into memory once.
        - The class is non-copyable and non-movable to ensure proper singleton behavior.
        - This allows any part of the program to access configuration settings using `Config::getInstance().get(...)`.

        This design makes it easy to extend or modify the game's behavior by simply editing a text-based configuration file.

        The code is located in:
        src/configuration/Config.h
        src/configuration/Config.cpp

3. Automatic Testing (based GTest):
        We implemented automated testing using the GoogleTest (GTest) framework.

        Description:
        - The test suite runs the game program on various predefined input files and compares the output to expected results.
        - The tests are defined as parameterized tests using TestWithParam, allowing easy scalability.
        - The test parameters are automatically generated for multiple test cases (e.g., input_a.txt, input_b.txt, etc.).

        Design Highlights:
        - GameTests is a test fixture class derived from ::testing::TestWithParam<GameTestParam>.
        - INSTANTIATE_TEST_CASE_P is used to create multiple test instances using generated file pairs.
        - The helper functions encapsulate file reading, output capturing, and line comparison logic.
        - This design ensures that testing is fast, automatic, and reproducible — enabling regression testing and early bug detection during development.

        The code is located in:
        test/tests.cpp
